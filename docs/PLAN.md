# Sarseo: خطة لبناء بديل لتطبيق Tarteel

## 1. تفكيك Tarteel إلى مكوّنات

| المكوّن | ما يفعله | التقنية المرجَّحة |
|---|---|---|
| التعرّف على التلاوة (ASR) | يحوّل صوت القارئ إلى نص قرآني | Whisper مضبوط على القرآن (Tarteel نشروا `whisper-tiny/base-ar-quran`) |
| مطابقة الآية (Alignment) | يحدد موضع القارئ في المصحف لحظيًا | بحث تقريبي في نص المصحف (n-gram / Levenshtein) على مخرجات ASR |
| كشف الأخطاء في الحفظ | كلمة ناقصة/زائدة/مبدَّلة، تخطي آية | مقارنة كلمة-بكلمة بين المتوقَّع والمسموع |
| أخطاء التشكيل/التجويد | حركات، مدود، غنة… | أصعب جزء: نموذج على مستوى الفونيمات/الحروف (CTC) بدل الكلمات |
| عرض المصحف | صفحات مصحف المدينة، تمييز الكلمة الحالية | بيانات QUL (خطوط وتخطيط الصفحات) |
| التلاوات الصوتية | الاستماع لقرّاء مع تزامن الكلمات | ملفات EveryAyah + توقيتات الكلمات |
| الحفظ والمتابعة | أهداف، ورد يومي، سجل الأخطاء، تكرار متباعد | قاعدة بيانات محلية + مزامنة سحابية |
| الحسابات والاشتراك | تسجيل دخول، Premium | Auth + بوابة دفع / اشتراكات المتاجر |

## 2. المعمارية المقترحة

```
[تطبيق جوال: Flutter أو React Native]
   ├─ تسجيل الصوت (16kHz mono) + VAD
   ├─ ASR على الجهاز (whisper.cpp / ONNX, نموذج tiny/base)  ← سرعة وخصوصية
   ├─ محرك المطابقة وكشف الأخطاء (محلي)
   ├─ عارض المصحف + قاعدة بيانات SQLite (النص، الصفحات، التوقيتات)
   └─ مزامنة ←→ [Backend: FastAPI/Supabase]
                    ├─ حسابات وتقدّم المستخدم
                    └─ ASR سحابي بنموذج أكبر (اختياري لدقة أعلى)
```

قرار أساسي: التشغيل **على الجهاز** أولًا (بلا تكلفة خوادم، يعمل دون إنترنت)، والسحابة اختيارية.

## 3. الموارد المفتوحة

- النماذج: [`tarteel-ai/whisper-base-ar-quran`](https://huggingface.co/tarteel-ai/whisper-base-ar-quran)، `tarteel-ai/whisper-tiny-ar-quran`، ومجتمعيًا [`whisper-large-v3-Tarteel`](https://huggingface.co/IJyad/whisper-large-v3-Tarteel).
- البيانات: `tarteel-ai/everyayah` (~127 ألف تسجيل، CC-BY 4.0).
- نص المصحف وبياناته: Tanzil، و QUL (qul.tarteel.ai)، و Quran.com API.
- التقييم: [Quran-Lab/quranic-asr-benchmark](https://huggingface.co/datasets/Quran-Lab/quranic-asr-benchmark) — يستبعد القرّاء المتداخلين مع بيانات التدريب.

> تحقّق من ترخيص كل مورد قبل الاستخدام التجاري.

## 4. مراحل التنفيذ

**المرحلة 0 – نموذج أولي (CLI بايثون)** ✅ منجزة (انظر README)
1. تحميل نص المصحف إلى SQLite.
2. تشغيل `whisper-base-ar-quran` على ملف صوتي → نص.
3. مطابقة النص مع المصحف → (سورة، آية، كلمة).
4. مقارنة كلمة-بكلمة → تقرير أخطاء.
5. قياس WER على benchmark.

**المرحلة 1 – ASR لحظي**: تقطيع الصوت (chunks + VAD)، بثّ النتائج، مطابقة تدريجية مع نافذة بحث حول الموضع الحالي.

**المرحلة 2 – تطبيق الجوال (MVP)**: عارض مصحف، زر تسميع، تمييز الكلمة الحالية، إخفاء الآيات (وضع الحفظ)، عرض الأخطاء.

**المرحلة 3 – الحفظ والمتابعة**: أهداف، سجل أخطاء، تكرار متباعد، مزامنة.

**المرحلة 4 – التشكيل والتجويد**: تدريب نموذج CTC على مستوى الحروف المشكّلة بدل الكلمات.

## 5. هيكل المستودع المقترح

```
Sarseo/
├─ docs/            الخطة والقرارات
├─ data/            سكربتات تجهيز نص المصحف والصوت (لا تُرفع البيانات الخام)
├─ engine/          بايثون: asr/ alignment/ mistakes/ eval/
├─ server/          FastAPI (لاحقًا)
└─ app/             تطبيق الجوال (لاحقًا)
```

## 6. المخاطر

- **الدقة**: النماذج الصغيرة على الجهاز أضعف؛ قِس WER مبكرًا.
- **تنوّع الأصوات**: بيانات EveryAyah قرّاء محترفون غالبًا؛ أصوات الأطفال والمبتدئين أصعب.
- **التجويد**: لا توجد بيانات مفتوحة كافية مُعلَّمة بأخطاء التجويد.
- **الهوية**: لا تستخدم اسم Tarteel أو شعاره أو تصميمه.
